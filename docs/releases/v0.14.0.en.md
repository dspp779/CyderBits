> [!IMPORTANT]
> **0.14 is the last release that supports macOS 10.15 and 11.** Later releases require macOS 12 or later.

## Highlights

- **Games keep running when you quit Cyder.** In 0.13.2, quitting Cyder while a game was running meant ending every game too; now ⌘Q closes only Cyder, and stopping the Windows environment is a separate action.
- **Fixed black textures with DXVK on Intel and AMD graphics**: maps, NPCs and monsters in TMS MapleStory render again ([#21](https://github.com/dspp779/CyderBits/pull/21)).
- **[cnc-ddraw](https://github.com/FunkyFr3sh/cnc-ddraw) can be turned on per game**, improving display, window modes and scaling in older DirectDraw games.
- **Apple developer tools are no longer needed.** Macs without Command Line Tools no longer get an install prompt and can use DXVK and switch MoltenVK.
- **New engine Cyder013**: MapleStory launch fixes, TMS on older Intel Macs with NVIDIA Kepler GPUs, and several macOS window fixes.
- **Faster launches**: preparing to start Wine now takes about 0.4 s instead of about 1.8 s.

## Game fixes

- **TMS MapleStory:** maps, NPCs and monsters were black with DXVK on Intel/AMD graphics. MoltenVK reports 4-bit texture formats there that Metal cannot create; DXVK now probes for usable formats and otherwise stores the texture as B8G8R8A8 and converts pixels ([#21](https://github.com/dspp779/CyderBits/pull/21)).
- **TMS MapleStory (older Intel Macs, NVIDIA Kepler):** Metal's shader compiler crashed at launch. MoltenVK 1.4.2 now uses MSL 2.4 on GPUs below GPU Family Mac 2 ([engine #11](https://github.com/dspp779/cyder-wine-engine/pull/11)); needs macOS 12+.
- **MapleStory:** two launch fixes from [GE-Proton](https://github.com/GloriousEggroll/proton-ge-custom): `CharPrevA`/`CharPrevExA` with a NULL start ([Wine bug 59926](https://bugs.winehq.org/show_bug.cgi?id=59926)) and `SPI_SETSTICKYKEYS`/`SPI_SETFILTERKEYS` reporting success ([Wine bug 59927](https://bugs.winehq.org/show_bug.cgi?id=59927)) ([engine #12](https://github.com/dspp779/cyder-wine-engine/pull/12)).
- **Umamusume: Pretty Derby (Traditional Chinese PC):** the login background was blank. After the engine was installed, GStreamer still looked for plugins at the build machine's paths and could not find the H.264 decoder; it now loads them from the engine's actual location and the background video plays, with both DXMT and GPTK ([#13](https://github.com/dspp779/CyderBits/pull/13), [issue #11](https://github.com/dspp779/CyderBits/issues/11)).
- **BlueCG HD:** colored stripes and a mode warning with cnc-ddraw, fixed by using a 32-bit display mode ([#19](https://github.com/dspp779/CyderBits/pull/19)).
- **Windowed DirectDraw games:** black screen. Backport of upstream Wine [`b5ab3b15`](https://gitlab.winehq.org/wine/wine/-/commit/b5ab3b15) ([engine #2](https://github.com/dspp779/cyder-wine-engine/pull/2)).
- **Cities: Skylines II:** added a DXMT candidate rule, off by default.

## New features and improvements

### Lifecycle

- **Quitting Cyder and stopping the Windows environment are separate.** ⌘Q and Quit close only Cyder; stopping the environment moved to Advanced. Quitting has a time limit even if background work is stuck.
- **An interrupted environment setup recovers without a reboot.** If a helper exits unexpectedly, Cyder cleans up the processes it started and releases the environment; a single damaged record no longer makes Cyder read-only.
- **More accurate environment and window tracking.** Cyder shows "unknown" instead of guessing, and updates on system events instead of polling every second.
- **The Game Library stays usable if the coordination service is unavailable**, and one failing environment no longer blocks the others.

### Graphics

- **MoltenVK/GPTK are not switched while games are running.** Both are shared by every environment on an engine; while programs are running, Cyder lists the environments in use and offers to stop them first.
- **DXVK checks MoltenVK's minimum macOS version before launching** and explains an incompatibility before Wine starts.
- **With GPTK installed, games no longer launch one at a time.** Cyder compared the GPTK path without handling the directory's trailing slash, so a correctly linked GPTK always looked like it needed switching. Every launch then took exclusive control of all environments and had to wait for the previous one. Cyder now compares the actual paths.

### DirectDraw (cnc-ddraw)

[cnc-ddraw](https://github.com/FunkyFr3sh/cnc-ddraw) reimplements DirectDraw (Cyder renders it with OpenGL). It fixes black screens, poor performance, crashes and window-switching problems common in old 2D games, and adds windowed, fullscreen and borderless modes with shader-based scaling.

- **Turn cnc-ddraw on per game** (Options → Display). Cyder loads it from the official cnc-ddraw 7.1 bundled with the app; nothing in the game folder is copied or replaced.
- **Runs windowed and keeps the aspect ratio by default**, so old games don't switch resolution or take over the screen.
- **Scaling filters: bilinear, Bicubic, Lanczos or nearest neighbor**, for sharper upscaling of low-resolution games on Retina displays, or to keep the pixel look; the frame rate can also be capped.
- Requires `native-ddraw-path-v1` in the Cyder013 engine.

### Scrolling

- **Scroll-wheel mode can be set per EXE**, with a new precise-scrolling option that is off by default; original values are kept for restoring. EXEs with the same name in one environment share the setting.
- **Applying scroll settings no longer starts Wine.**

### Settings and UI

- **"Rebuild" split into "Repair" and "Full Reset".** Repair keeps installed programs, saves and registry settings; only Full Reset clears the environment, and it can be undone.
- **More responsive menus and Game Library**: resource reads, icons, file lookups, settings and diagnostics writes moved to the background.
- **Failed launches clear their progress and show the reason**; about 1–2% of launches are no longer misreported as settings-read failures when settings are saved at the same moment.
- Removed the Game Library shortcut from Preferences; fixed Settings window initialization and late progress updates.

### Diagnostics and security

- **Component integrity diagnostics cover Wine system files inside the environment**, so files removed by antivirus software can be told apart ([#20](https://github.com/dspp779/CyderBits/pull/20), [issue #12](https://github.com/dspp779/CyderBits/issues/12)).
- **DXMT's `winemetal.so` is signed with Cyder's Developer ID**, reducing antivirus and security prompts (issue #12).

## Known issues

- **DXVK 2 is not included** and remains future work; a DXVK 2 choice in old settings switches to DXVK. DXVK 2.7.1 has not passed game testing, and MoltenVK/Metal cannot yet provide the `robustBufferAccess2`, null descriptor and D3D11 transform feedback support it needs.
- **The MoltenVK version is shared by every environment on an engine**; close all Windows programs on that engine before switching.
- **macOS 10.15/11 can only use MoltenVK 1.2.10**, so the Kepler fix does not apply there.
- Precise scrolling is verified to write and restore its settings; how it feels in each game and with each input device still needs checking.
- When process ownership or a request's result cannot be confirmed, the UI shows unknown/pending and never resends.
- When the diagnostics log is full, entries are dropped and counted; if writing stays blocked, quitting wins and the last diagnostics may not be saved.
- macOS 10.15 completes first-time setup in Terminal and uses Bash for file selection and launching; the full native UI needs macOS 11+.
- This release makes no claim about game FPS or first-load stutter.
