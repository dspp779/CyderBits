> [!IMPORTANT]
> **0.14 is the last Cyder release that supports macOS 10.15 and 11.** Later releases require macOS 12 or later. On macOS 10.15/11, 0.14 still runs DXVK (with MoltenVK 1.2.10).

## Highlights

- **Quitting Cyder no longer closes your games.** ⌘Q closes only Cyder; stopping the Windows environment is now a separate action.
- **Fixed black textures with DXVK on Intel and AMD graphics**: maps, NPCs and monsters in TMS MapleStory render again.
- **cnc-ddraw can be turned on per game**, so older DirectDraw games no longer need changes to their folders.
- **New engine Cyder013**: MapleStory launch fixes, TMS on older Intel Macs with NVIDIA Kepler GPUs, and several macOS window fixes.
- **Faster launches and a more responsive UI**: preparing a launch now takes about 0.4 s instead of about 1.8 s.

## Upgrading

- **Replace the old app with the new one.** Environments, installed games, saves and registry settings are kept; the engine update is applied in place.
- **DXMT reinstalls once.** DXMT now uses its upstream version number `0.80` instead of `0.80-cyder.N`; the content is unchanged. Cyder switches over automatically when no Windows program is running.
- **"Rebuild" is now "Repair".** Repair keeps the environment's contents; only "Full Reset" clears it, and that can be undone.
- **Your MoltenVK setting is kept.** The `1.4.2` / `1.2.10` menu selects the MoltenVK version (DXVK is always 1.10.3). macOS 10.15/11 can only use 1.2.10.
- The experimental "DXVK 2" option in old settings is switched to DXVK automatically.

## New features and improvements

### Lifecycle

- **Quitting Cyder and stopping the Windows environment are separate.** ⌘Q and Quit close only Cyder; stopping the environment moved to Advanced. Quitting has a time limit even if background observation or diagnostics writing is stuck.
- **An interrupted environment setup no longer needs a reboot to recover.** If a helper exits unexpectedly, Cyder cleans up the processes that operation started and releases the environment; a single damaged record no longer makes Cyder read-only.
- **More accurate environment and window tracking.** State is restored from process identity, environment generation and verifiable window information, and shows "unknown" instead of guessing; updates are driven by system events instead of once-a-second polling.
- **The Game Library stays usable if the coordination service is unavailable**, and one failing environment no longer blocks the others.

### Graphics

- **MoltenVK/GPTK are not switched while games are running.** Both are shared by every environment on an engine; while programs are still running, Cyder lists the environments in use and offers to stop them first.
- **DXVK checks MoltenVK's minimum macOS version before launching** and explains an incompatibility before Wine starts.
- **Command Line Tools are no longer required.** Macs without developer tools used to see an install prompt and could not launch with DXVK or switch MoltenVK.
- **With GPTK installed, launches no longer queue behind each other.**

### DirectDraw (cnc-ddraw)

- **cnc-ddraw can be turned on per game** (Options → Display). The DLL loads from the official cnc-ddraw bundled with Cyder; nothing in the game folder is copied or replaced. New Bicubic and Lanczos scaling filters. Requires `native-ddraw-path-v1` in the Cyder013 engine.

### Scrolling

- **Scroll-wheel mode can be set per EXE**, with a new precise-scrolling option that is off by default. Settings go to that EXE's AppDefaults and the original values are kept for restoring. EXEs with the same name in one environment share the setting.
- **Applying scroll settings no longer starts Wine**; nothing happens when values are already correct.

### Settings and UI

- **Faster launcher**: preparing to start Wine drops from about 1.8 s to about 0.4 s.
- **"Rebuild" split into "Repair" and "Full Reset".**
- **More responsive menus and Game Library**: resource reads, icons, file lookups, settings and diagnostics writes moved to the background.
- **Failed launches clear their progress and show the reason**; about 1–2% of launches are no longer misreported as settings-read failures when settings are saved at the same moment.
- Removed the Game Library shortcut from Preferences; fixed Settings window initialization and late progress updates.

### Media and diagnostics

- **Video keeps playing after the engine is moved.** GStreamer plugins and the scanner now load from the engine's actual location, so the H.264 decoder is found ([#13](https://github.com/dspp779/CyderBits/pull/13), [issue #11](https://github.com/dspp779/CyderBits/issues/11)).
- **Component integrity diagnostics cover Wine system files inside the environment**, so files removed by antivirus software can be told apart ([#20](https://github.com/dspp779/CyderBits/pull/20), [issue #12](https://github.com/dspp779/CyderBits/issues/12)).
- **DXMT's native `winemetal.so` is signed with Cyder's Developer ID**, reducing antivirus and security prompts (issue #12).

## Game fixes

- **TMS MapleStory:** fixed black maps, NPCs and monsters with DXVK on Intel/AMD graphics. MoltenVK reports 4-bit texture formats there that Metal cannot create; DXVK now probes for usable formats and otherwise stores the texture as B8G8R8A8 and converts pixels ([#21](https://github.com/dspp779/CyderBits/pull/21)).
- **TMS MapleStory (older Intel Macs, NVIDIA Kepler):** no longer crashes Metal's shader compiler at launch. MoltenVK 1.4.2 uses MSL 2.4 on GPUs below GPU Family Mac 2 ([engine #11](https://github.com/dspp779/cyder-wine-engine/pull/11)). The fix is in MoltenVK 1.4.2, so it needs macOS 12+.
- **MapleStory:** two Wine launch fixes from [GE-Proton](https://github.com/GloriousEggroll/proton-ge-custom): `CharPrevA`/`CharPrevExA` with a NULL start ([Wine bug 59926](https://bugs.winehq.org/show_bug.cgi?id=59926)) and `SPI_SETSTICKYKEYS`/`SPI_SETFILTERKEYS` reporting success ([Wine bug 59927](https://bugs.winehq.org/show_bug.cgi?id=59927)) ([engine #12](https://github.com/dspp779/cyder-wine-engine/pull/12)).
- **BlueCG HD:** cnc-ddraw uses a 32-bit display mode, fixing colored stripes and the mode warning ([#19](https://github.com/dspp779/CyderBits/pull/19)).
- **Windowed DirectDraw games:** fixed a black screen (backport of upstream Wine [`b5ab3b15`](https://gitlab.winehq.org/wine/wine/-/commit/b5ab3b15), [engine #2](https://github.com/dspp779/cyder-wine-engine/pull/2)).
- **Cities: Skylines II:** added a DXMT candidate rule, off by default.

## Known issues

- **DXVK 2 is not included** and remains future work. DXVK 2.7.1 has not passed game testing; MoltenVK/Metal cannot yet provide the `robustBufferAccess2`, null descriptor and D3D11 transform feedback support it needs.
- **The MoltenVK version is shared by every environment on an engine**; close all Windows programs on that engine before switching.
- **macOS 10.15/11 cannot use MoltenVK 1.4.2**, so the Kepler fix above does not apply there.
- Precise scrolling is verified to write and restore its settings; how it feels in each game and with each input device still needs checking.
- When process ownership or a request's result cannot be confirmed, the UI keeps an unknown/pending state and never resends an uncertain request.
- When the diagnostics log is full, entries are dropped and counted; if writing stays blocked, quitting wins and the last diagnostics may not be saved.
- macOS 10.15 completes first-time setup in Terminal and uses Bash for file selection and launching; the full native UI needs macOS 11+.
- This release makes no claim about game FPS or first-load stutter. Notarization does not mean game compatibility has been verified.
