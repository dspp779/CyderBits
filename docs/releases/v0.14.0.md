> [!IMPORTANT]
> **0.14 是最後支援 macOS 10.15 與 11 的 Cyder 版本。** 之後的版本只支援 macOS 12 以上。0.14 在 macOS 10.15／11 上仍可使用 DXVK（MoltenVK 1.2.10）。

## 重點

- **退出 Cyder 不再關掉遊戲。** ⌘Q 只關閉 Cyder，遊戲繼續執行；停止 Windows 環境改為獨立操作。
- **修正 Intel／AMD 顯示卡上 DXVK 的黑色貼圖**，TMS 新楓之谷的地圖、NPC 與怪物恢復正常。
- **每個遊戲可單獨開啟 cnc-ddraw**，舊 DirectDraw 遊戲不必再改動遊戲資料夾。
- **新引擎 Cyder013**：楓之谷啟動修正、舊款 Intel Mac（NVIDIA Kepler）可執行 TMS、多項 macOS 視窗修正。
- **啟動更快、介面更少等待**：Wine 啟動前的準備由約 1.8 秒降到約 0.4 秒。

## 升級須知

- **直接以新版取代舊版即可。** 既有環境、已安裝的遊戲、存檔與登錄都會保留；引擎更新時以原地方式套用。
- **DXMT 會重新安裝一次。** DXMT 改為沿用上游版本號 `0.80`（取代先前的 `0.80-cyder.N` 名稱），內容未變；Cyder 會在沒有 Windows 程式執行時自動切換。
- **「重建」改名為「修復」。** 「修復」保留環境內容；只有「完全重設」會清除環境，且可復原。
- **MoltenVK 版本設定沿用。** 選單中的 `1.4.2`／`1.2.10` 是 MoltenVK 版本（DXVK 固定為 1.10.3）。macOS 10.15／11 只能使用 1.2.10。
- 舊設定中的實驗性「DXVK 2」選項會自動改為 DXVK。

## 新功能與改進

### 生命週期

- **退出 Cyder 與停止 Windows 環境分開。** ⌘Q 與退出選單只關閉 Cyder；停止環境移到「進階」。背景觀察或診斷寫入卡住時，退出仍有時限。
- **中斷的環境準備不再需要重新開機才能恢復。** 輔助程式意外結束時，Cyder 會清理該次操作啟動的程序並釋放環境；單一損壞紀錄不再讓 Cyder 變成唯讀。
- **環境與視窗辨識更精確。** 依程序身分、環境世代與可驗證的視窗資訊恢復狀態，資訊不足時顯示未知而非猜測；狀態更新改由系統事件觸發，不再每秒輪詢。
- **協調服務無法使用時，遊戲庫仍可瀏覽**，一個環境失敗也不會卡住其他環境。

### 圖形

- **遊戲執行中不切換 MoltenVK／GPTK。** 這兩個元件由同一引擎的所有環境共用；仍有程式執行時，Cyder 會列出使用中的環境，並可選擇先停止它們。
- **DXVK 啟動前檢查 MoltenVK 的最低 macOS 版本**，不相容時在啟動 Wine 之前說明原因。
- **不再需要 Command Line Tools。** 先前未安裝開發者工具的 Mac 會跳出安裝提示，且無法用 DXVK 啟動或切換 MoltenVK。
- **安裝 GPTK 後，啟動不再互相排隊。**

### DirectDraw（cnc-ddraw）

- **每個遊戲可開關 cnc-ddraw**（選項 → 顯示）。DLL 從 Cyder 內建的官方 cnc-ddraw 載入，不複製或替換遊戲資料夾內的檔案；縮放濾鏡新增 Bicubic 與 Lanczos。此功能需要 Cyder013 引擎的 `native-ddraw-path-v1`。

### 捲動

- **每個 EXE 可分別設定滾輪模式**，新增預設關閉的精確捲動；設定寫入該 EXE 的 AppDefaults，並保留原值以便還原。同一環境中同名的 EXE 共用設定。
- **套用捲動設定不再啟動 Wine**；值已正確時不做任何事。

### 設定與介面

- **啟動器更快**：Wine 啟動前的準備由約 1.8 秒降到約 0.4 秒。
- **「重建」拆成「修復」與「完全重設」。**
- **選單與遊戲庫更即時**：資源讀取、圖示、檔案查詢、設定與診斷寫入都移到背景。
- **啟動失敗時清除進度並顯示原因**；設定與啟動同時發生時，不再有約 1–2% 的啟動被誤判為設定讀取失敗。
- 偏好設定移除遊戲庫捷徑，並修正設定視窗初始化與晚到的進度更新。

### 媒體與診斷

- **搬移引擎後影片仍可播放。** GStreamer 外掛與掃描程式改從實際的引擎位置載入，不再找不到 H.264 解碼器（[#13](https://github.com/dspp779/CyderBits/pull/13)、[Issue #11](https://github.com/dspp779/CyderBits/issues/11)）。
- **元件完整性診斷涵蓋環境內的 Wine 系統檔**，可分辨防毒軟體刪除環境檔案的情況（[#20](https://github.com/dspp779/CyderBits/pull/20)、[Issue #12](https://github.com/dspp779/CyderBits/issues/12)）。
- **DXMT 的原生元件 `winemetal.so` 以 Developer ID 簽署**，減少防毒與系統安全提示（Issue #12）。

## 遊戲修正

- **TMS 新楓之谷：** 修正 Intel／AMD 顯示卡上 DXVK 的黑色地圖、NPC 與怪物。MoltenVK 在這些 GPU 宣稱支援 4-bit 貼圖格式，Metal 卻無法建立；DXVK 現在會實測可用格式，不支援時以 B8G8R8A8 儲存並轉換像素（[#21](https://github.com/dspp779/CyderBits/pull/21)）。
- **TMS 新楓之谷（舊款 Intel Mac、NVIDIA Kepler）：** 不再於啟動時讓 Metal 編譯服務崩潰。MoltenVK 1.4.2 對 GPU Family Mac 2 以下的顯示卡改用 MSL 2.4（[engine #11](https://github.com/dspp779/cyder-wine-engine/pull/11)）。此修正在 MoltenVK 1.4.2，需 macOS 12 以上。
- **楓之谷：** 修正啟動時的兩個 Wine 問題，取自 [GE-Proton](https://github.com/GloriousEggroll/proton-ge-custom)：`CharPrevA`／`CharPrevExA` 起點為 NULL（[Wine bug 59926](https://bugs.winehq.org/show_bug.cgi?id=59926)），以及 `SPI_SETSTICKYKEYS`／`SPI_SETFILTERKEYS` 回報成功（[Wine bug 59927](https://bugs.winehq.org/show_bug.cgi?id=59927)）（[engine #12](https://github.com/dspp779/cyder-wine-engine/pull/12)）。
- **BlueCG HD：** 啟用 cnc-ddraw 時改用 32-bit 顯示模式，修正彩色條紋與模式警告（[#19](https://github.com/dspp779/CyderBits/pull/19)）。
- **視窗模式 DirectDraw 遊戲：** 修正黑畫面（backport 上游 Wine [`b5ab3b15`](https://gitlab.winehq.org/wine/wine/-/commit/b5ab3b15)，[engine #2](https://github.com/dspp779/cyder-wine-engine/pull/2)）。
- **Cities: Skylines II：** 新增 DXMT 候選規則，預設停用。

## 已知問題

- **DXVK 2 不隨本版提供**，列為未來工作。DXVK 2.7.1 尚未通過遊戲實測；MoltenVK／Metal 目前無法提供它需要的 `robustBufferAccess2`、null descriptor 與 D3D11 transform feedback。
- **MoltenVK 版本由同一引擎的所有環境共用**，切換前需關閉該引擎的所有 Windows 程式。
- **macOS 10.15／11 無法使用 MoltenVK 1.4.2**，因此上述 Kepler 修正不適用於這些系統。
- 精確捲動已確認設定寫入與還原；各遊戲與輸入裝置的實際手感仍需個別確認。
- 無法確認程序歸屬或要求結果時，介面會保留未知／待確認狀態，不會自動重送不確定的要求。
- 診斷日誌寫滿時會丟棄並計數；寫入持續受阻時以退出為優先，最後的診斷可能沒有寫入。
- macOS 10.15 透過 Terminal 完成首次設定並以 Bash 選檔／啟動；完整的原生介面需 macOS 11 以上。
- 本版未宣稱遊戲 FPS 或首次載入卡頓有改善。公證通過不代表遊戲相容性已驗證。
