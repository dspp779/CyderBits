# Cyder 0.14.0 — 生命週期與介面改善

> 正式版本：`0.14.0`（Developer ID + 公證）  
> Engine：`CX26.3.0-W11-Cyder013`

0.14.0 包含退出與停止環境分離、啟動要求與環境恢復重寫、捲動相容設定、每遊戲 cnc-ddraw、MoltenVK 版本切換保護，以及選單與遊戲庫的回應速度。引擎更新為 `CX26.3.0-W11-Cyder013`，並重新封裝 DXVK 與簽署 DXMT；未納入仍在研究中的 DXMT 效能修改。

## 本版修改

### 生命週期

- **退出 Cyder 與停止 Windows 環境分開。** Command-Q 與退出選單只關閉 Cyder，遊戲繼續執行；停止 Windows 環境改為「進階」中的獨立操作。背景觀察或診斷寫入卡住時，退出仍有期限。
- **啟動要求只在記憶體中保存。** rc.1 的持久要求紀錄已移除：它從不清理，約 512 次啟動後會永久無法啟動；重開 Cyder 也不再有待恢復或可能重播的歷史要求。重複傳送的同一要求仍只執行一次。
- **中斷的環境準備不再卡到重新開機。** 準備中的輔助程式意外結束時，Cyder 會清理該操作啟動的程序並釋放環境，之後即可再次啟動；單一損壞的紀錄不再讓 Cyder 進入唯讀狀態。
- **環境與視窗辨識更精確。** 依程序出生身分、環境世代與可驗證的視窗資訊恢復狀態；缺少證據時保留未知狀態。狀態更新改由系統事件觸發，不再每秒輪詢。
- **協調服務不可用時仍保留介面。** 遊戲庫及唯讀資訊可繼續使用，失敗環境不阻塞其他環境。

### 圖形

- **執行中不切換 MoltenVK／GPTK。** 這兩個元件由同一引擎的所有環境共用，遊戲可能在執行途中才載入。只要該引擎仍有 Wine 程序在執行，Cyder 就拒絕切換並列出使用中的環境，可選擇停止它們後再啟動；無法完整讀取程序清單時同樣拒絕。
- **修正非 Apple GPU 上 DXVK 的黑色貼圖。** MoltenVK 在 Intel／AMD GPU 宣告支援 4-bit 格式，但 Metal 無法建立該類貼圖，使 TMS 楓之谷的地圖、NPC 與怪物呈黑色。DXVK 改為實測可用格式，不支援時以 B8G8R8A8 儲存 `B4G4R4A4` 並轉換像素。
- **安裝 GPTK 後不再讓每次啟動獨占所有環境。** 路徑比對錯誤使每次啟動都排隊執行，現已修正。
- **DXVK 啟動前檢查 MoltenVK 的最低 macOS 版本。** 讀取實際 dylib 的 minOS，不符時在啟動 Wine 前說明原因。
- **不再需要 Command Line Tools。** 讀取 MoltenVK 檔案資訊改用內建方式；先前未安裝開發者工具的 Mac 會跳出安裝提示，並無法以 DXVK 啟動或切換 MoltenVK。

### DirectDraw（cnc-ddraw）

- **每個遊戲可開關 cnc-ddraw。** 在「選項 → 顯示」以開關啟用；Cyder 從共用的官方元件載入 DLL，不複製遊戲、不替換遊戲目錄內的 DLL。縮放濾鏡新增 Bicubic 與 Lanczos，在確認啟用後才可調整。需要引擎宣告 `native-ddraw-path-v1`（Cyder013 起）。

### 捲動

- **每個 EXE 可分別設定滾輪模式。** 新增預設關閉的精確捲動開關，遊戲可沿用或覆寫；設定寫入該 EXE 的 AppDefaults 並保留原值備份，不更動整個環境的預設值。同一環境中同名的 EXE 共用設定。
- **套用設定不再啟動 Wine。** 值已符合時不做任何事；環境閒置時直接修改登錄檔，執行中才使用一次 `reg` 指令。

### 設定與介面

- **啟動器更快。** Wine 啟動前的準備時間由約 1.8 秒降至約 0.4 秒；未安裝 Command Line Tools 的 Mac 不再跳出安裝提示。
- **「重建」改為「修復」與「完全重設」。** 修復（預設）重新解開引擎並就地更新環境，保留已安裝程式、存檔與登錄；完全重設才清除環境，且可復原。

- **儲存設定時不再拒絕啟動。** 設定與啟動同時發生時，先前約 1–2% 的啟動會被誤判為設定讀取失敗。
- **啟動失敗時清除進度。** 要求被拒時關閉準備／啟動進度並顯示原因。
- **選單與遊戲庫減少等待。** 選單使用狀態快照；資源讀取、圖示、檔案查詢、設定與診斷寫入移至背景。
- **簡化偏好設定。** 移除偏好設定中的遊戲庫捷徑；修正設定視窗初始化與晚到的進度更新。

### CompatDB

- 新增 Cities: Skylines II 的 DXMT 候選規則（預設停用）。

### 引擎（Cyder012 → Cyder013）

- **原生 ddraw 路徑（`native-ddraw-path-v1`）。** ntdll 在程序啟動時讀取一次 `CYDER_DDRAW_PATH`，只把 `ddraw`／`ddraw.dll` 的載入導向指定的絕對路徑；Wine 的 native／builtin 規則不變。
- **楓之谷啟動修正（取自 GE-Proton）。** `CharPrevA`／`CharPrevExA` 起點為 NULL（Wine bug 59926），以及 `SPI_SETSTICKYKEYS`／`SPI_SETFILTERKEYS` 回報成功（Wine bug 59927）。
- **舊款 Intel Mac（Kepler GPU）可執行 TMS。** MoltenVK 1.4.2 在舊 GPU 上限制 MSL 版本。
- **視窗修正。** 縮到 Dock 的視窗可透過輔助使用功能還原；原生全螢幕缺少排序依據時不再失敗；GL front-buffer 呈現修正。
- **wined3d GL 的 Shader Model 5（feature level 11）**，預設關閉，以 `WINE_D3D_CONFIG=renderer=gl,CyderGLShaderModel5=1` 個別啟用。
- **磁碟可用空間查詢失敗時改查實際掛載的磁碟**，不再回報虛構的可用空間。
- **兩個 MoltenVK 版本（1.4.2、1.2.10）皆以 macOS 12 為最低版本建置。**

## 已知限制

- **DXVK 2 不隨本版出貨，列為未來工作。** DXVK 2.7.1 尚未通過遊戲實測；MoltenVK／Metal 目前無法提供其所需的 `robustBufferAccess2`、null descriptor 與 D3D11 transform feedback 語意。App 與引擎皆不含 `dxvk2` payload，設定中的舊 `dxvk2` 選項會遷移為 DXVK。
- MoltenVK 版本是整個引擎共用的設定：要改用另一版本，需先關閉該引擎的所有 Windows 程式；不支援同時以不同版本執行不同遊戲。
- 精確捲動已確認登錄值寫入與還原；不同遊戲與輸入裝置的實際手感仍需個別確認。
- 無法確認程序歸屬或要求結果時，介面可能保留未知／待確認狀態；不自動重派不確定的要求。
- 一般診斷日誌滿載時可丟棄並記數；寫入持續受阻時退出優先，最後診斷可能未落盤。
- Apple Silicon 執行 Wine 仍需要可用的 Rosetta。DXVK 所需的 MoltenVK（1.4.2 與 1.2.10）皆需 macOS 12+；較舊系統無法以切換版本使用 DXVK。macOS 10.15 使用 Terminal bootstrap／Bash 路徑，完整原生 UI 需 macOS 11+。
