## 重點

- **退出 Cyder 時遊戲可繼續執行。** 0.13.2 在遊戲執行中退出 Cyder，必須同時結束所有遊戲；現在 ⌘Q 只關閉 Cyder，停止 Windows 環境改為獨立操作。
- **修正 Intel／AMD 顯示卡上 DXVK 的黑色貼圖**，TMS 新楓之谷的地圖、NPC 與怪物恢復正常（[#21](https://github.com/dspp779/CyderBits/pull/21)）。
- **每個遊戲可單獨開啟 [cnc-ddraw](https://github.com/FunkyFr3sh/cnc-ddraw)**，改善舊 DirectDraw 遊戲的顯示、視窗模式與縮放。
- **不再需要 Apple 開發者工具。** 未安裝 Command Line Tools 的 Mac 不再跳出安裝提示，也能使用 DXVK 與切換 MoltenVK。
- **新引擎 Cyder013**：楓之谷啟動修正、舊款 Intel Mac（NVIDIA Kepler）可執行 TMS、多項 macOS 視窗修正。
- **啟動更快**：Wine 啟動前的準備由約 1.8 秒降到約 0.4 秒。

## 遊戲修正

- **TMS 新楓之谷：** Intel／AMD 顯示卡上 DXVK 的地圖、NPC 與怪物呈黑色。MoltenVK 在這些 GPU 宣稱支援 4-bit 貼圖格式，Metal 卻無法建立；DXVK 改為實測可用格式，不支援時以 B8G8R8A8 儲存並轉換像素（[#21](https://github.com/dspp779/CyderBits/pull/21)）。
- **TMS 新楓之谷（舊款 Intel Mac、NVIDIA Kepler）：** 啟動時 Metal 的 shader 編譯服務崩潰。MoltenVK 1.4.2 對 GPU Family Mac 2 以下的顯示卡改用 MSL 2.4（[engine #11](https://github.com/dspp779/cyder-wine-engine/pull/11)）；需 macOS 12 以上。
- **楓之谷：** 修正兩個啟動問題，取自 [GE-Proton](https://github.com/GloriousEggroll/proton-ge-custom)：`CharPrevA`／`CharPrevExA` 起點為 NULL（[Wine bug 59926](https://bugs.winehq.org/show_bug.cgi?id=59926)），以及 `SPI_SETSTICKYKEYS`／`SPI_SETFILTERKEYS` 回報成功（[Wine bug 59927](https://bugs.winehq.org/show_bug.cgi?id=59927)）（[engine #12](https://github.com/dspp779/cyder-wine-engine/pull/12)）。
- **賽馬娘 Pretty Derby（繁中 PC 版）：** 登入畫面背景空白。引擎安裝後，GStreamer 仍從建置機的路徑尋找外掛，找不到 H.264 解碼器；現在從實際的引擎位置載入，背景影片恢復播放，DXMT 與 GPTK 皆適用（[#13](https://github.com/dspp779/CyderBits/pull/13)、[Issue #11](https://github.com/dspp779/CyderBits/issues/11)）。
- **BlueCG HD：** 啟用 cnc-ddraw 時出現彩色條紋與模式警告，改用 32-bit 顯示模式後修正（[#19](https://github.com/dspp779/CyderBits/pull/19)）。
- **視窗模式的 DirectDraw 遊戲：** 黑畫面。backport 上游 Wine [`b5ab3b15`](https://gitlab.winehq.org/wine/wine/-/commit/b5ab3b15)（[engine #2](https://github.com/dspp779/cyder-wine-engine/pull/2)）。
- **Cities: Skylines II：** 新增 DXMT 候選規則，預設停用。

## 新功能與改進

### 生命週期

- **退出 Cyder 與停止 Windows 環境分開。** ⌘Q 與退出選單只關閉 Cyder；停止環境移到「進階」。背景作業卡住時，退出仍有時限。
- **中斷的環境準備不需重新開機即可恢復。** 輔助程式意外結束時，Cyder 會清理該次啟動的程序並釋放環境；單一損壞紀錄不再讓 Cyder 變成唯讀。
- **環境與視窗辨識更精確。** 資訊不足時顯示未知而非猜測；狀態改由系統事件更新，不再每秒輪詢。
- **協調服務無法使用時遊戲庫仍可瀏覽**，一個環境失敗不會卡住其他環境。

### 圖形

- **遊戲執行中不切換 MoltenVK／GPTK。** 兩者由同一引擎的所有環境共用；仍有程式執行時，Cyder 會列出使用中的環境，並可先停止它們。
- **DXVK 啟動前檢查 MoltenVK 的最低 macOS 版本**，不相容時在啟動 Wine 前說明原因。
- **安裝 GPTK 後，遊戲不再只能逐一啟動。** Cyder 比對 GPTK 路徑時沒有處理目錄結尾的斜線，已正確連結的 GPTK 永遠被判定為需要切換，每次啟動都取得全部環境的獨占權限，只能一個接一個執行。現改為比對實際路徑。

### DirectDraw（cnc-ddraw）

[cnc-ddraw](https://github.com/FunkyFr3sh/cnc-ddraw) 重新實作 DirectDraw（Cyder 以 OpenGL 繪製），修正舊 2D 遊戲常見的黑畫面、效能低落、崩潰與切換視窗問題，並提供視窗／全螢幕／無邊框模式與 shader 縮放。

- **每個遊戲可開關 cnc-ddraw**（選項 → 顯示）。Cyder 從內建的官方 cnc-ddraw 7.1 載入，不複製或替換遊戲資料夾內的檔案。
- **預設以視窗模式執行並保持畫面比例**，避免舊遊戲切換解析度或搶佔全螢幕。
- **縮放濾鏡可選雙線性、Bicubic、Lanczos 或最近鄰**，在 Retina 螢幕放大低解析度畫面時更清晰，或保留像素風格；也可限制影格率。
- 需要 Cyder013 引擎的 `native-ddraw-path-v1`。

### 捲動

- **每個 EXE 可分別設定滾輪模式**，新增預設關閉的精確捲動；原值會保留以便還原。同一環境中同名的 EXE 共用設定。
- **套用捲動設定不再啟動 Wine。**

### 設定與介面

- **「重建」拆成「修復」與「完全重設」。** 修復保留已安裝程式、存檔與登錄；完全重設才清除環境，且可復原。
- **選單與遊戲庫更即時**：資源讀取、圖示、檔案查詢、設定與診斷寫入移到背景。
- **啟動失敗時清除進度並顯示原因**；設定與啟動同時發生時，不再有約 1–2% 的啟動被誤判為設定讀取失敗。
- 偏好設定移除遊戲庫捷徑，並修正設定視窗初始化與晚到的進度更新。

### 診斷與安全

- **元件完整性診斷涵蓋環境內的 Wine 系統檔**，可分辨防毒軟體刪除環境檔案的情況（[#20](https://github.com/dspp779/CyderBits/pull/20)、[Issue #12](https://github.com/dspp779/CyderBits/issues/12)）。
- **DXMT 的 `winemetal.so` 以 Developer ID 簽署**，減少防毒與系統安全提示（Issue #12）。

## 已知問題

- **不含 DXVK 2**，列為未來工作；舊設定中的 DXVK 2 會自動改為 DXVK。DXVK 2.7.1 尚未通過遊戲實測，MoltenVK／Metal 也無法提供它需要的 `robustBufferAccess2`、null descriptor 與 D3D11 transform feedback。
- **MoltenVK 版本由同一引擎的所有環境共用**，切換前需關閉該引擎的所有 Windows 程式。
- **macOS 10.15／11 只能使用 MoltenVK 1.2.10**，因此 Kepler 修正不適用於這些系統。
- 精確捲動已確認設定寫入與還原；各遊戲與輸入裝置的實際手感仍需個別確認。
- 無法確認程序歸屬或要求結果時，介面會顯示未知／待確認，不會自動重送。
- 診斷日誌寫滿時會丟棄並計數；寫入持續受阻時以退出為優先，最後的診斷可能沒有寫入。
- macOS 10.15 以 Terminal 完成首次設定，並以 Bash 選檔／啟動；完整的原生介面需 macOS 11 以上。
- 本版未宣稱遊戲 FPS 或首次載入卡頓有改善。
