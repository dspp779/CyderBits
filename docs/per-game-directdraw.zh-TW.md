# 每遊戲 DirectDraw

在遊戲庫選取遊戲，開啟「選項 → 顯示」，按「啟用 cnc-ddraw」。Cyder 會從共用的官方元件載入 DLL，遊戲仍從原來的位置啟動；啟用時不建立遊戲副本，也不替換遊戲目錄內的 DLL。

圖形轉譯請選「預設」或 WineD3D。cnc-ddraw 的啟用、停用及已啟用選項變更會立即儲存，從下次啟動生效；高解析度、圖形轉譯及其他選項仍透過視窗底部的「套用」儲存。已開啟的遊戲及啟動器維持本次啟動時取得的設定。

| 選項 | 行為 |
|---|---|
| 平滑（雙線性） | 使用 CNC 的 Bilinear 縮放，為預設值。 |
| 銳利（最近鄰） | 保留明顯的像素邊界，放大時可能看見階梯。 |
| 畫面更新上限 | 限制 CNC 的畫面呈現頻率，預設 60；不等同遊戲邏輯速度。 |
| 停用 cnc-ddraw | 下次啟動恢復原本的 DLL 搜尋方式。已執行的遊戲不會中途換 DLL。 |
| 驗證／更新 | 核對 app 內的官方封裝並儲存目前設定。 |

## 啟動器與多開

每個遊戲庫項目以 EXE 的實體完整路徑識別。對啟動器啟用 CNC 後，正常繼承環境的遊戲子程序會使用該啟動器的 DLL 與設定檔。一個啟動器連續開出的視窗預設使用同一份啟動設定；後續在 Cyder 修改偏好，會用於下一次由 Cyder 建立的啟動程序。

即使共用同一個 Windows 環境（prefix），分別由 Cyder 啟動的程序也能使用各自的 DirectDraw 設定。Cyder 為每份設定產生以內容雜湊命名的唯讀 INI，保留舊檔供仍存活的子程序讀取；新設定不覆寫舊 INI。DLL 載入路徑與 INI 路徑只傳給最後的遊戲／啟動器程序，不傳給建立 prefix 的準備工具，也不寫入 prefix 的共用 DLL overrides。

此隔離範圍是 DirectDraw DLL 與 CNC 設定。其他 Wine 選項仍依各自的共用或獨立環境規則運作。若啟動器自行重建子程序環境並移除 Cyder 傳入的變數，需針對該啟動器另行處理；一般 CreateProcess 繼承與自訂環境移除的差異已有控制測試。

## BlueCG

目前設定針對已辨識的 32 位元 BlueCG 客戶端與核心。請在原版 `BlueLauncher.exe` 選 HD[1]（961 × 721、32 位元）。也可沿用已由真正啟動器觀察並保存的直接啟動參數。

`BlueLauncher.exe` 與 `bluecg.exe` 若各自加入遊戲庫，會有各自的 DirectDraw 偏好。遊戲由哪個項目啟動，就取得該項目的設定；啟動器子程序沿用啟動器設定。

2026-11-09 的隔離原型已證明 BlueCG 可從原遊戲目錄載入外部官方 CNC DLL，並以程序記憶體標頭及 native／builtin 身分核對。使用者另回報可執行且放大沒有階梯。這些證據不取代新整合版本的啟動器、多開、輸入與正常退出驗收，也不代表正式畫質或功耗比較完成。

## 舊版遊戲副本

舊版建立的副本、備份及收據會保留。若選項顯示舊版 DLL 安裝方式，先關閉該遊戲及其啟動器，按「還原舊版 DLL」；有未完成切換時先按「修復上次切換」。確認原版已還原後，可對同一個遊戲位置啟用新的外部載入模式。

還原後的備份與來源記錄不會刪除。若 DLL 或備份已有不明變更，Cyder 會提示衝突並保留檔案。新模式的停用只修改 Cyder 偏好，不再切換遊戲目錄的 DLL。

## 元件與支援範圍

Cyder 使用 [cnc-ddraw v7.1.0.0 官方發行版](https://github.com/FunkyFr3sh/cnc-ddraw/releases/tag/v7.1.0.0)，固定核對封裝、DLL、授權及必要資源的雜湊。官方 CNC 為 32 位元 DLL；64 位元遊戲與其他遊戲版本需另行驗證。

外部載入需要引擎宣告 `native-ddraw-path-v1`，且實際 PE ntdll 具有對應功能標記。舊引擎會明確拒絕啟用中的外部方案，不以啟動成功推論 DLL 已正確替換。引擎目前重導向以 `ddraw`／`ddraw.dll` 名稱提出的載入請求；明確指定其他完整路徑的載入請求仍按原規則處理。

Cyder 偏好保存在支援目錄的 `directdraw` 下，啟動用 INI 位於選定 prefix 的 `C:\CyderCncDdraw`。INI 使用 `savesettings=0`，不把某個視窗的大小或位置回寫給其他程序。未知圖形 wrapper、互斥圖形後端或手動 DLL override 會先顯示衝突，讓使用者選擇一套有效設定。
