## 不可退讓的行為

- 主執行緒不做程序／視窗掃描、磁碟輪詢或同步等待背景工作；開選單立即使用快照。遵守 Apple menuWillOpen、menuDidClose、menuNeedsUpdate 契約。
- 退出 Cyder 只退出自身與監控，遊戲繼續；停止 Windows 環境是獨立明確動作。包含 Command-Q、選單與 AppKit 終止路徑。
- 同 prefix 共用環境監控，但不推定遊戲歸屬；有證據才認領，無證據可獨立顯示或保留未知。
- NGS／無視窗背景程序仍在時，環境入口正確保留，不無限轉圈、不稱為清理中。
- 可靠接管與去重，取消不偽報，重開不重播未知要求；舊 observer／executor 事件不能影響新世代。
- 程式／視窗點擊需確認目標，能力不足不提供假動作；不搶焦點、不把切換失敗處理成重新啟動。
- wineserver -w 是背景等待機制，不等於每款遊戲壽命；實際解決返回後的可靠校準與錯誤傳遞，不能以永久 unknown 規避正常收尾。
- 使用 Apple 官方文件核對涉及的 API／HIG；工程時間目標與 Apple 要求分開註明。

## 驗證方式：先真實，再有根據地替代

1. 先記錄基線：現有相關測試、可重現缺陷、可用 engine／macOS／CPU 架構與測試入口。測試版需確認由本次修改建置，避免測到舊 app。既有失敗須調查，不一律當成既有問題。
2. 先測原生 Cyder：用實際 NSMenu tracking、視窗、Command-Q、重新開啟及可及性操作；採工具提供的 UI 狀態／截圖辨識，不盲點。不要因 Wine 是 x86 就預設 computer use 無法操作。
3. 在隔離 prefix 嘗試真實 x86 Wine：單／多視窗、root 先退出、背景無視窗留存、環境排空、退出 Cyder 後程式留存及重新接回。可使用最小 Windows 測試程式重現具體行為。
4. Wine 視窗的 accessibility 不足時，若 computer use 支援可用畫面與輸入，嘗試基於實際畫面的有限操作；不能繞過工具權限。記錄實際失敗是工具能力、顯示、權限、架構還是產品缺陷。相同原因重複失敗後換方法，不無限重試。
5. 無法可靠完成真實操作時，使用依賴注入、事件重放、可控制時鐘、原生輔助程序／視窗，以及 journal／socket 故障注入。替身必須驅動正式 reducer、coordinator、menu rendering 與 action 路徑，不能另寫一個會通過的假 app 代替產品。
6. 替身至少涵蓋 ACK 遺失、dispatch 前後 crash、取消競態、舊事件晚到、PID 重用、掃描卡住、快速開關選單、多 bottle、NGS 類型無視窗殘留、停止與新啟動交錯、恢復中退出。固定可重現案例，必要時加入固定種子的排列測試。
7. NGS 類型替身只能驗證生命週期政策，不能宣稱實際 NGS／反作弊相容。最小 x86 Wine 視窗測試通過也不代表所有遊戲相容。

## 使用者體驗與量測

驗收 rollout 文件 V01–V14，並評估能否不用閱讀診斷文字就理解目前狀態與下一步。

- 首屏及選單不等待完整背景掃描；慢／失敗觀察時一般操作與退出仍可用。
- 正常流程無多餘確認、成功通知或恢復警告；錯誤回饋有可行動入口，不連續彈窗。
- 選單排序穩定、標題可辨、鍵盤／VoiceOver 標籤合理；停止範圍明確，資訊列不冒充操作。
- 在記錄清楚的測試條件下，初始工程目標為選單開啟 p95 ≤100ms、沒有本功能造成的單次主執行緒阻塞 ≥250ms；至少採樣 30 次並保留原始量測。用可用的 Instruments／signpost／event-loop 記錄找原因。若無法量到真正點擊至呈現延遲，明確標示 callback 等代理指標，不把它換名當端到端延遲。
- 環境噪音或工具不足時，保留基線、分布及可歸因證據；不能任意放寬目標或刪除失敗樣本來過關。以上數字是本任務工程目標，不是 Apple 官方門檻。
